## 环境

需要 Node.js 24.x（至少 24.15.0）、npm、Rust 和目标平台的 Tauri 开发依赖；Windows 检查工作流配置为 Node.js 24.22.1。前端依赖通过 `package-lock.json` 固定，Rust 依赖通过各 crate 的 `Cargo.lock` 固定。

仓库包含五个 Rust 构建入口：`protocol/`、`client/`、`core/`、`cli/`、`src-tauri/`。修改共享逻辑时，在 `core/` 中实现，避免在桌面和 CLI 中各写一份。

## 从源码运行桌面应用

在仓库根目录执行：

```sh
npm ci
npm run tauri dev
```

Tauri 开发命令会先构建 debug CLI，再启动 Vite 和桌面后端。前端改动使用热更新；Rust 改动需要重新编译后端。日常界面开发不需要反复生成安装包。

桌面开发服务不监听 `.cache/`、`docs-site/` 和 `browser-extension/build/`，文档及扩展构建不会触发桌面窗口刷新。

只启动前端开发服务器：

```sh
npm run dev
```

前端服务器不能替代 Tauri 的本地文件与检索接口。验证完整桌面流程时使用 Tauri 开发入口。

## Web 样式预览（开发中）

在仓库根目录运行 `npx vite --host 127.0.0.1 --port 1427 --strictPort`，然后在本机访问 `http://127.0.0.1:1427/tests/visual/`。预览复用桌面工作区，侧栏和“关于”显示 Super-SAG；窄屏使用可收起的侧栏。访问 `/tests/visual/?fixture=conversation` 可查看虚构会话与引用；访问 `/tests/visual/?fixture=search` 并输入“示例流程”可查看预设搜索结果；访问 `/tests/visual/?fixture=files` 可查看虚构目录、文档编辑与新建时的保存位置选择。浏览器回归中的会话搜索、消息编辑、流式回答、工具状态和确认弹窗同样使用测试数据与事件，不执行真实工具。页面标注虚构数据，仅用于界面开发，不连接真实目录、索引或模型，也不是可部署的 Web 服务。未实现的写操作会报错。

用户反馈 Windows 全部业务及保留数据升级已通过实机测试。不要将该测试预览对外提供服务。

该预览会修改同一浏览器源下的部分 `sag.*` 本地存储；请使用独立浏览器配置和专用回环端口。窄屏侧栏的文件夹操作菜单目前存在遮挡及切换后抽屉未关闭的问题。上述预览属于 Windows 基准验收前的开发预研，正式 Web 对照须以验收通过的 Super-SAG Windows 安装版为准。

### B/S 界面开发

新的浏览器入口在当前桌面组件上逐项适配。运行 `npm run build:web:ui` 可构建界面代码；当前尚无 Web 业务服务，入口会明确提示服务未接通。隔离测试夹具、浏览器检查和范围限制见仓库中的 `tests/bs/README.md`。该构建不是部署包，不能用于真实知识库。

## 构建 CLI

```sh
npm run build:cli:dev
npm run build:cli
```

前者生成 debug CLI，后者生成 release CLI。开发产物放在 `src-tauri/bin/development/`，正式产物放在 `src-tauri/bin/`；macOS 产物会执行签名步骤。

需要把当前构建安装到用户终端时，显式执行：

```sh
./src-tauri/bin/sag install cli
super-sag --version
```

安装器检查归属、校验值和构建渠道，对每个暂存文件校验后替换；更新旧命令失败时会尝试恢复新命令的原状态。开发桌面不自动更新正式 CLI；开发 CLI 也拒绝覆盖已登记的正式安装。Rust 源码变更后重新执行 `npm run build:cli:dev`，让桌面和服务使用相同构建身份，再重新启动桌面。

## 构建桌面应用

```sh
npm run build
npm run tauri build
```

Windows 使用：

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run package:windows
```

构建安装包不需要额外的本机参考项目。升级 Node.js 后应在新终端确认 `node --version`，并重新执行 `npm.cmd ci`。

需要 Windows x64、Node.js 24.x（至少 24.15.0）、Rust stable 的 `x86_64-pc-windows-msvc` 目标、Microsoft C++ 构建工具和 WebView2；构建时还需联网取得依赖及 NSIS 工具。每条命令失败时应先排查，不要继续安装。预计安装器位于 `src-tauri/target/release/bundle/nsis/`，以实际产物为准。

安装器构建成功不代表 Windows 验收通过。须先在隔离环境核验全新安装与原版覆盖升级，记录安装包 SHA-256、数据和原件；不要覆盖唯一一份业务数据。当前未发布 Super-SAG 独立 npm 包或签名更新通道。

macOS 原生构建入口：

```sh
npm ci
npm run check
npm run package:macos
```

该命令配置为生成 `.app`、`.dmg` 并检查应用内容；Apple 芯片和 Intel 的实际验证仍在进行。当前配置使用临时签名，不代表 Developer ID 签名、公证及对外分发已通过；如未提供经校验的 Safari 扩展安装包，桌面构建会禁用 Safari 扩展导出。

## 代码检查

```sh
npm run check
npm test
cargo test --manifest-path protocol/Cargo.toml
cargo test --manifest-path client/Cargo.toml
cargo test --manifest-path core/Cargo.toml
cargo test --manifest-path cli/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

桌面构建与检查依赖本地 CLI 资源时，先执行 `npm run build:cli:dev`。用独立数据目录进行手动开发检查，避免影响日常知识库：

```sh
SAG_DATA_DIR=/path/to/dev-data npm run tauri dev
SAG_DATA_DIR=/path/to/dev-data ./src-tauri/bin/development/sag service status
```

桌面与 CLI 共用同一份开发数据时，设置相同的 `SAG_DATA_DIR`。服务退出后会按需启动，退出桌面不会停止服务；测试结束可执行 `super-sag service stop`。需要模型服务的功能使用开发者自行配置的凭据；纯索引和本地匹配不需要 API 密钥。

## 文档与仓库边界

`docs/` 保存当前架构、开发指南、接口说明与明确标记的设计计划。实现变化时更新相应文档，避免追加多份相互冲突的历史说明。

开发产物、临时输出、日志、截图和本地数据不提交到文档目录。凭据与用户知识库不进入发布包。自动化测试代码及必要 fixture 保留在各自的测试目录。

## 网页剪藏扩展

运行 `npm run build:clipper` 构建 Chrome / Edge 扩展包，产物位于 `src-tauri/clipper/`。macOS 安装完整 Xcode 后，可运行 `npm run build:clipper:safari` 构建 Safari 本地测试应用，产物位于 `browser-extension/build/`。测试版使用独立的 `com.sag.webclipper.development` 标识，避免干扰已安装的正式扩展。

准备正式 Safari 应用时，运行 `node browser-extension/build.mjs --safari --release`，再完成应用和 DMG 的签名、公证。macOS 桌面端构建使用 `src-tauri/clipper/sag-web-clipper-safari.dmg` 中已公证的安装包，也可通过 `SAG_CLIPPER_SAFARI_DMG` 指定路径；校验未通过时停止构建。桌面端构建不会用未签名测试包覆盖正式包。
