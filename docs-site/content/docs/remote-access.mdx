## 网页服务

### 部署边界

Super-SAG 的 B/S 部署以一台主机为服务端：`super-sag` 后台服务负责知识库、索引、配置和模型请求，CLI 内置的 Web 资源负责返回浏览器页面。没有单独的 Web 前端进程、Node/Vite 生产服务器或独立数据库部署步骤；桌面端只是可选的本机控制界面。服务端主机和后台进程必须持续运行，浏览器可来自本机或局域网设备。

已经安装桌面端时，可在 **设置 → 远程服务** 开启网页服务。无桌面服务器直接使用 CLI，最小启动流程如下：

```sh
export SAG_DATA_DIR="$HOME/.local/share/super-sag" # 可选，指定主机数据目录
super-sag add /srv/super-sag-library         # 首次部署时加入并索引目录
super-sag api web access-code on              # 建议保留访问码
super-sag api web start --host 0.0.0.0 --port 24681
super-sag api status
```

`api status` 输出的本机或局域网地址才是浏览器地址；`0.0.0.0` 只是监听地址，不能直接粘贴到浏览器。访问码用 `super-sag api web code` 查看。单独运行 `super-sag api start` 只开启 HTTP API/MCP，不会代替 `api web start` 开启浏览器页面；停止网页使用 `super-sag api web stop`，停止整个后台服务使用 `super-sag service stop`。

从源码部署时，在仓库根目录运行 `npm ci && npm run build:cli`，再运行 `./src-tauri/bin/sag install cli` 安装当前用户的 CLI，打开新终端后使用上面的 `super-sag` 命令。构建过程会把 `dist-web` 资源嵌入 CLI，因此不需要另行运行 Node/Vite 服务器。若需主机开机自动恢复后台和已保存的网页服务，网页启动后运行 `super-sag api autostart enable`。若必须使用 `/var/lib` 等系统目录，请先让当前服务用户拥有该目录。

1. 使用桌面端时，打开 **设置 → 远程服务**，开启 **网页服务**。
2. 在本机点击地址旁的打开按钮，或在同一局域网的其他设备上打开显示的局域网地址。
3. 网页访问码开启时，点击 **复制访问码**，将访问码粘贴到浏览器登录页。同一浏览器再次打开同一地址时会自动连接，点击 **退出** 可清除记住的访问码。关闭访问码时会直接进入知识库。

首次登录页按浏览器首选语言显示，支持简体中文、繁体中文、英语、日语、韩语和西班牙语，其他语言使用英语。已连接过的网页在当前页面上退出或需要重新连接时，会沿用知识库的界面语言。

点击 **更换访问码** 并确认后，旧码立即失效，已登录的浏览器需要重新输入新码。网页服务保持开启，API Key 不受影响。关闭网页服务也会使旧码失效。

网页服务运行时显示 **网页访问码** 开关。Linux 新配置默认关闭访问码，macOS 和 Windows 新配置默认开启。已有安装继续使用保存的设置。关闭访问码后，任何能打开网页地址的人都可以直接进入知识库，修改共享设置、管理 API Key 或清除应用数据。重新开启会生成新访问码。此开关不会改变网页服务的监听地址，也不会关闭 API 或 MCP 的鉴权。


在 **API 和 MCP** 下方的 **连接配置** 中，选择 **仅本机** 可限制为本机访问。选择 **本机与局域网** 后，同一局域网的其他设备也可连接。若无法修改连接配置，请先关闭正在运行的远程服务。

## 网页功能

网页支持浏览文件、新建和编辑 Markdown、搜索、问答、保存笔记和查看索引进度。网页与桌面端共用文件、索引和问答历史。

手机窄屏默认隐藏侧栏。点击左上角按钮展开，点击侧栏外或收起按钮关闭。侧栏展开时覆盖页面，正文宽度保持不变。

进入会话或搜索结果后，顶部居中显示 **问答** 或 **搜索**。打开文档时使用文档工具栏。点击左上角的箭头返回上一层。搜索时，关键词和搜索按钮在第一行，搜索范围和模式在第二行。提交搜索或发送问题后，键盘会自动收起。

在侧栏打开 **设置** 后，可调整通用、外观、文件、模型、问答和搜索设置，配置在线数据源，管理 CLI 权限、API 和 MCP 服务及 API Key，也可以在 **数据与隐私** 中清空对话、移除所有目录或清除应用数据。设置在同一服务的所有浏览器间共享。手机上使用页面顶部的分类菜单。点击底部的 **保存设置** 应用更改，远程服务操作即时生效。

如果网页提示缺少模型，可以直接打开 **设置 → 模型设置**。快速搜索无需配置模型。

在网页打开 **设置 → 远程服务 → 网页访问码**，可开启或关闭验证、复制访问码和更换访问码。开启验证或更换访问码后，发起操作的浏览器会自动用新码继续连接，其他浏览器需要输入新码。

网页服务的启停、监听地址、端口和开机自启在主机上管理。接入本机 Agent、配置外部 MCP 工具和从主机导入文件也需要在主机上操作。通过网页清除应用数据后，当前网页服务的地址与访问码继续有效。

「网页剪藏」入口仅在桌面端设置中显示。Linux 网页端可通过上传文件、上传文件夹或连接在线数据源添加资料。

内置 HTTP 连接不加密，请在可信局域网内使用。服务端电脑和后台服务需保持运行，桌面窗口可以关闭。

## 在网页创建文件夹和上传

1. 点击侧栏 **文件夹管理** 右侧的 **＋**，或在 **文件** 总览点击 **创建文件夹**。输入名称后，网页会打开该文件夹。
2. 进入网页创建的文件夹后，**创建文件夹** 和 **新建文档** 放在一起。旁边的 **上传文件** 和 **上传文件夹** 分别用于上传单个文件和整个目录。
3. 上传的文件会保留相对目录结构，并按 **文件设置** 建立索引。同名文件会提示冲突，已有文件会保留。

网页创建的目录存放在运行 Super-SAG 的主机上，位置是 **应用数据目录**下的 `web-library`。可以在 **设置 → 数据与隐私** 查看应用数据目录。每个文件最多 512 MB，隐藏文件和浏览器未传递的空子目录不会上传。

主机上已有的目录可继续通过 `super-sag add /路径/文件夹` 接入。它们保留在原位置，可以在同一网页浏览和搜索。网页上传会写入网页创建的目录。

## 通过 CLI 开启

支持 `super-sag api web` 的独立 CLI 可在 **Windows x64、macOS Apple Silicon 和 Linux** 上运行网页服务。Linux 支持 Ubuntu 24.04 和 Debian 12（x86_64 / ARM64）。

在 Linux 上可按[开发指南](/zh/docs/development)从源码构建 CLI，再用 `super-sag --version` 检查。

在运行 CLI 的电脑上打开终端，运行 `super-sag add` 并指定本机文件夹路径，将目录加入知识库并建立索引。用 `super-sag list` 查看索引状态；用 `super-sag remove` 并指定目录路径可取消接入，原文件会保留。完整用法见 [CLI 命令](/zh/docs/cli#命令)。

```sh
super-sag api web start --host 0.0.0.0
super-sag api status
```

Linux 新配置可直接打开网页。要在启动网页服务前开启验证，可以先运行 `super-sag api web access-code on`，再启动网页服务并用 `super-sag api web code` 查看访问码。也可用 `super-sag api web access-code off` 关闭验证。设置即时生效，重启后保留。

`0.0.0.0` 表示监听所有 IPv4 网卡，访问范围由网络和防火墙决定。仅在本机访问时，使用 `--host 127.0.0.1`。默认端口为 `24681`；若改过端口，省略 `--port` 会沿用已保存的设置。

在本机打开 `super-sag api status` 显示的本机地址，或在同一局域网内的其他设备上打开局域网地址。看到登录页时输入访问码。运行 `super-sag api web stop` 可关闭网页服务。

## 通过公网 IP 或域名访问

如果公网 IP 映射到内网 IP，请在主机上用 `super-sag api web external-url` 保存浏览器实际打开的完整地址。

```sh
super-sag api web external-url http://203.0.113.10:24681
```

把示例 IP 换成实际地址。保存后可用 `super-sag api status` 查看。保存地址不会开启网页服务，也不会更改访问码开关或放行防火墙端口。需要网页服务时再运行 `super-sag api web start --host 0.0.0.0`，并在防火墙和云安全组中仅对需要访问的来源放行端口。访问码关闭时，能连接的人可以直接进入知识库。

地址必须包含 `http://` 或 `https://`；非默认端口要写明。通过 HTTPS 反向代理访问时，填入浏览器使用的 HTTPS 地址；代理负责 HTTPS，并须保留原始请求的主机名和端口。其他外部地址仍会被拒绝，本机和局域网地址仍可使用。

运行 `super-sag api web external-url --clear` 可清除外部地址。
