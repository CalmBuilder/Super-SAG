# 02 Web 样式优先与业务等效

状态：已有仅用于开发的 Web 视觉预研及所列浏览器检查；Windows 正式基准尚未验收，现有切片均须在基准冻结后复核。窄屏侧栏菜单遮挡和预览本地存储隔离问题尚未修复；正式 Web、其余界面状态、完整品牌替换和业务均待逐项实施与验收，不能用旧 Web 原型代替。

## 第一优先级：对齐 Windows 样式

完成 Windows 和 macOS 个人桌面版验收后，冻结 Windows 安装包、源码、环境和测试资料，作为 Web 正式对照基准；具体记录项见[Windows 基准](01-Windows品牌与升级.md#冻结正式-web-基准)。开发者本机只读参考中的 `App.svelte`、`src/components` 及用户的原 Windows 截图用于前期预研和辅助核对，不能代替已验收的 Super-SAG Windows 安装版。工作代码应优先抽取或复用同源 Svelte 组件、样式、翻译和交互状态，而不是另写一套管理卡片界面。Web 的身份和租户入口在后续阶段作为增量融入现有界面。

视觉清单至少覆盖：

| 页面/状态 | 对照点 |
| --- | --- |
| 公共框架 | 左侧品牌与文件夹树、顶部问答/搜索/文件切换、内容区、按钮、字体、边距、圆角、图标及浅/深色。 |
| 问答 | 空状态、模型/范围选择、输入与会话列表；会话内容、流式回答、引用、来源和操作按钮。 |
| 搜索 | 空状态、搜索范围、快速/深入模式、输入区、结果、原文定位及返回。 |
| 文件 | 空目录、多层树、目录和文件列表、统计、筛选、预览、创建/编辑。 |
| 添加文件夹 | 目录浏览、多选、返回上层、隐藏项、索引选项和确认/取消，按服务器端可授权目录适配。 |
| 设置 | 通用、外观、文件、网页剪藏、快捷键、模型、问答、搜索、CLI、隐私、关于及其滚动/保存/关闭状态。 |

以相同视口、显示缩放、语言、主题和虚构数据比较截图与交互；覆盖常用桌面尺寸和 320、375、768 像素等边界。逐屏对照内容、字体字号、图标、背景、布局和交互，保留可比较截图及差异；少数节点的坐标、字体族和前景色相同不能证明整页像素一致。浏览器与 Windows 原生能力差异逐项记录并与用户确认，不能静默删掉其他功能。对没有等同测试数据的页面不宣称像素或状态已通过。用户提供的截图用于结构对照，正式截图使用脱敏演示数据。

可为视觉比对制作**仅限开发/测试环境**的确定性测试替身，目标是不写入真实数据，明确标注其局限，也不能把模拟按钮或假结果称为业务已实现；当前同源浏览器存储尚未隔离，须按下方差异登记处理。交付的服务必须通过真实服务端接口实现相应功能。每个视觉小切片用真实 Chromium 验收，记录窗口尺寸、环境、对照、结果和尚存差异；最终还须结合用户的 Windows 实机确认。

当前[开发预览](../../tests/visual/index.html)直接加载工作树的桌面组件，并使用仅回环可访问的虚构数据和测试替身。侧栏和设置“关于”使用 Super-SAG 标识，浏览器不显示原生窗口按钮；959 像素及以下使用可键盘操作的侧栏抽屉。桌面应用已使用当前品牌，原生安装及实际业务仍须验收。预览不是 Web 服务，不读取服务器目录或真实文件。独立参考源码对照和启动方法见[实施记录](05-实施记录.md)与[测试说明](../../tests/browser/README.md)。

| 差异 | 当前预研及待办 | 状态 |
| --- | --- | --- |
| Windows 最小化、最大化、关闭及托盘 | 预览未显示原生窗口按钮；逐项提出浏览器或服务运行方式，并核对关闭页面后的行为。 | 待方案及确认 |
| 窄屏布局 | 预览在 959px 及以下使用抽屉、480px 及以下调整部分控件；320/375px 文件夹选项菜单被抽屉遮挡，且从菜单切换工作区后抽屉未关闭、主区仍不可操作。修复并复测后，连同桌面基准逐项确认适配差异。 | 缺陷未修复；待确认 |

视觉测试应使用独立浏览器 profile 和独立回环 origin。当前测试预览在同一 origin 下仍会写 `sag.onboarding.seen` 等本地存储，模拟搜索会更新 `sag.search.history`；不得在可能存有真实状态的 origin 打开，存储隔离和对应回归待修复，详见[审核](07-多角色审核.md)。

## 业务对齐

1. 将目前通过 [`src/lib/api.ts`](../../src/lib/api.ts) 和各组件直接调用的 Tauri 命令、事件、窗口、对话框、快捷键等依赖盘点为能力契约。保留原桌面实现，Web 通过明确的业务接口和用户绑定事件接入；禁止直接向浏览器暴露任意本地命令或 `protocol::Operation` 的通用代理。
2. 服务器目录采用用户明确授权的 Linux 目录作为主要知识来源。沿桌面交互选择目录、直接读取和索引，保留层级、原文件、格式和索引更新语义；上传本地资料只是补充。测试目录的路径、软链接、变化、权限及故障都要实测。
3. 逐项复用原有 SAG 核心的格式识别/转换、目录扫描、索引、快速与深入搜索、Jev、模型、工具、答案、引用、历史、文件编辑和设置行为。每项先建立与桌面相同输入/参数的测试基准，再接入 Web；未接通的功能标记为未完成。
4. 服务端把 Web 用户/租户上下文和目录资源边界预留在契约中；单用户视觉/业务开发使用隔离测试目录，不能把开发预览的无鉴权服务直接作为多用户服务暴露。后续加入权限时不得改掉原业务语义。
5. 按新架构实现 Linux 启动与停止、状态、日志和持久化；最终 `app.sh` 监听 `0.0.0.0:8167`。监听地址、同源校验、HTTPS/反向代理和文件访问必须与部署环境及阶段目标匹配。

业务对照必须使用相同真实测试文件及配置，比较原件摘要、目录、索引、搜索结果和引用来源。模型回答可能不确定，需分别验证可控模型与真实模型的可追溯结果，不能只比固定全文或 HTTP 状态。
