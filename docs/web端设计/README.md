# Super-SAG 改造方案

本目录根据用户重新确认的目标，从干净的 SAG-Wiki 代码重新编写。当前已开始 Windows 桌面品牌和安装器兼容改造，并保留此前仅用于开发的 Web 视觉切片；不表示 Windows 安装包、全部 Web 界面或 Web 业务已经完成。实施和验收以本目录的记录为准。

## 已确认的目标

- 产品名和标识为 **Super-SAG**；参考图形已保存于 [`assets/branding`](../../assets/branding/)。Windows 和 Web 使用同一品牌。
- 固定对照源码是 [`pros/SAG-Wiki`](../../pros/SAG-Wiki/)，只读保留；工作源码在本仓库根目录。以 SAG-Wiki 的目录、知识库、索引、检索、问答、文件和设置逻辑为基准。正式 Web 对照使用完成构建并通过实机验收的 Super-SAG Windows 安装版；静态源码和原版安装包用于辅助核对，不能假定它们与该安装版是同一构建。
- Windows 桌面保持本地单用户、无需登录；新版按**覆盖升级原 SAG-Wiki、保留原有数据**设计，必须实际验证安装和升级。
- **先完成并实机验收 Super-SAG Windows 桌面版**，冻结安装包和测试基准；再在 Linux Web 中先完整还原其样式、布局和交互，逐项接通对应业务能力，最后叠加身份和多租户。桌面和 Web 最终都使用 Super-SAG 标识。已有 Web 视觉切片保留为预研，不能替代 Windows 验收或正式 Web 对照。
- Linux 服务器上的授权目录是主要知识库来源；浏览器上传为补充。参考 WeKnora 的范围仅限用户、租户、成员及权限，不改用它的知识库业务或界面。
- 旧 Web 原型不迁入新项目：旧页面、服务端、权限代码、数据库结构及数据均不迁移；旧成果原地保留，后续仅复用权限设计与测试经验。启动入口重新实现 `app.sh`，保留所需的使用方式，目标监听 `0.0.0.0:8167`。
- 每个实施小阶段完成正常、极值、边界和失败验证，Web 相关阶段须通过真实浏览器回归；Windows 桌面及安装升级还须在 Windows 上实际验证。用户将在自己的 Windows 电脑上按提供的步骤验收并反馈。
