# 01 Windows 品牌、打包与覆盖升级

状态：品牌与安装器源码改造中，待 Windows 构建和实机验收；具体步骤见[Windows 构建与实机验收](08-Windows构建与实机验收.md)。

## 目标

从当前工作仓库生成 Super-SAG Windows 安装包，界面和功能以静态 SAG-Wiki 参考及用户提供的 Windows 版为基准；桌面继续本地单用户、免登录。用户要求新安装包覆盖已有 SAG-Wiki，同时保留文件夹、索引、设置、模型配置、会话、笔记和原始文件。

## 实施约束

1. 复用已确认的 [`super-sag-icon.svg`](../../assets/branding/super-sag-icon.svg) 和 PNG，逐一核对桌面侧栏、关于、主窗口、托盘、任务栏、快捷搜索、安装器、卸载入口及图标。中英文产品展示统一为 Super-SAG；上游项目署名、许可证及引用必须准确保留。
2. 原源码的 Tauri 标识为 `com.sag.desktop`，默认数据路径由 [`protocol/src/cli.rs`](../../protocol/src/cli.rs) 决定。覆盖升级须保留或显式兼容原标识、数据定位、CLI、桌面设置及相关协议；不为了展示名称改掉目录并丢失旧数据。技术目录含 `sag-wiki` 不代表可随意改名。
3. [`installer-hooks.nsh`](../../src-tauri/windows/installer-hooks.nsh) 对运行进程和快捷方式有既定处理；产品名变更可能影响 NSIS 卸载项、安装位置、旧快捷方式和版本识别。需要根据实际生成的安装包和 Windows 注册信息验证，不能假设仅保留标识即可覆盖升级。
4. 版本号、签名与更新源要防止把原版和 Super-SAG 当成已发布的同一发行。当前源码的上游更新配置须逐项核对；没有独立可用的发布与签名链时，不伪造下载地址，也不让改造版静默安装上游版本。此项要与 Windows 覆盖升级兼容一起验证。
5. 依锁文件构建；已有脚本包括 `npm run package:windows`，实际目标、依赖和产物位置由 Windows 构建结果确认。打包前记录 Node、Rust、MSVC、WebView2、依赖锁、构建提交和安装包 SHA-256；构建日志不得包含凭据。
6. 实机前准备可审查的 Windows 构建步骤、隔离数据与备份/恢复步骤和逐项记录表。覆盖升级需核对默认数据目录及 `SAG_DATA_DIR`、`SAG_DESKTOP_DATA_DIR` 指定的目录；记录实际安装目录、注册项、旧/新二进制、进程和快捷方式。新旧同为 `0.2.7` 时不得假定安装器允许或正确处理覆盖。
7. 对已有用户配置也验证更新源和签名策略，防止迁移后的持久化设置继续指向上游发行；当前客户端启动时会检查更新，此后每 8 小时检查一次，下载及安装需要用户操作。新的独立发布与签名链尚未确认前，必须同时处理启动时检查、已有配置及安装路径，不能默认沿用上游发行和签名信任。核对升级后实际生效的桌面、CLI 与后台服务路径、版本及构建标识，并验证彼此通信：同版本但构建不同的 CLI 可能被保留，不能只检查 `sag --version` 是否可运行。

## 安装和升级验收

- 使用隔离 Windows 测试环境：先安装用户提供的原版，使用虚构目录和文件建立索引、设置、问答会话及笔记，并记录各原文件摘要、配置和可恢复备份；然后运行 Super-SAG 安装包，验证原安装被正确升级，账号无需登录、数据和原件保持可用，搜索和历史能打开。
- 同时验证全新安装、重复安装、覆盖后重启、CLI、桌面/开始菜单快捷方式、图标、托盘及卸载行为。测试异常中断、旧程序占用、同版本/新版本安装及恢复路径；不得未经验证就覆盖用户唯一业务数据。
- 覆盖安装前后逐项对照问答、搜索、文件、文件夹选择、设置和快捷键。问答使用可控模型夹具以及可用时的真实模型分别记录；模型密钥不得进入截图或仓库。
- 以同一组隔离测试文件及其摘要验证文件夹层级、多格式、忽略规则、索引、快速/深入搜索、Jev、模型、问答引用、文件编辑、移除后原文件保留、设置、CLI/Agent；覆盖正常、极值、边界、失败及恢复。记录应用和实际服务/CLI 的路径、版本、构建标识、安装包 SHA-256 及配置来源，不记录密钥。
- 用真实浏览器核对受影响的可复用前端样式和文档，但 Tauri 桥接模拟、Linux 构建或浏览器截图不等于 Windows 安装、原生窗口和升级验收。Windows 真实结果由用户按步骤反馈后才能关闭对应验收项。

## 冻结正式 Web 基准

Windows 全新安装与隔离覆盖升级的必选验收通过后，记录实际验收安装包 SHA-256、版本、签名/渠道、构建源码提交及工作树差异、锁文件摘要、Windows 版本、显示缩放、主题、语言、脱敏截图和测试文件/目录摘要。若安装包或相关源码再次改变，重新评估并复测受影响基线。Web 正式逐项对照以这份已验收的 Super-SAG Windows 基准为准；原版 SAG-Wiki 安装包与固定源码仍作为升级和差异参考。
