# 07 多角色需求与实施审核

> 本报告记录 Windows 改造前的审核快照。其后已开始 Windows 源码改造，部分“当前”描述和 Web 预研源码摘要不再对应现有工作树；后续状态见[实施记录](05-实施记录.md)。本报告中的浏览器缺陷未声明已修复。

审核日期：2026-11-10。审核角色分别覆盖需求/方案、当前前端与浏览器证据、Windows 升级与租户隔离；本次核对范围为 `本仓库根目录` 当前工作树，不是 Windows 实机或真实 Web 服务验收。

## 结论与顺序调整

现有方案覆盖了 SAG-Wiki 产品能力、桌面免登录、Linux 授权目录、业务对齐后再加多租户和 `app.sh` 目标，但**不完全符合本次重述的严格顺序**：矩阵曾把 Windows 验收列为后续阶段门槛，却又允许 Web 视觉准备交叉推进；交接还把继续 Web 视觉列为下一步。在尚无 Super-SAG Windows 安装包和实机验收的情况下，上次工作主要推进了 Web 视觉预览。它符合当时文档允许交叉准备的表述，但没有满足本次“先完成并验收 Windows，再以其为 Web 基准”的优先级。

现已将[实施矩阵](04-实施与验收.md)和[交接](06-新会话交接.md)改为：先完成 Windows 品牌、打包、隔离覆盖升级和实机验收，冻结实际安装包和对照资料；再逐屏完成 Web 样式与交互、逐项接通业务，最后实施多租户。已做的 Web 视觉切片保留为预研，不回退、不记作正式 Web 阶段通过，待 Windows 基准冻结后复测。涉及桌面共享代码的当前改动亦待 Windows 原生回归。

用户本轮确认：旧权限与隔离成果**只复用设计和测试经验，旧代码及数据库不迁入**。旧 Web 页面、后端、权限代码、数据库结构和数据均不迁移；旧成果和旧数据原地保留。本项目方案、记录和证据在 `本仓库的 docs/web端设计/`；需求引文中的 `旧项目的 docs/web端设计/` 为旧项目历史位置，本次未向旧项目写入。

## 本次真实浏览器发现：未通过

独立审核使用 Chromium 156.0.8078.4、随机回环端口、临时 Vite 缓存、独立浏览器 profile 和虚构数据；没有访问用户文件或真实业务数据。可运行 [`audit_preview.py`](../../tests/browser/audit_preview.py) 复现；它在问题存在时返回非零。机器记录与脱敏截图分别见[审核结果](验收证据/12-Web预览审核.json)和[320 像素菜单截图](验收证据/12-web-sidebar-menu-320.png)。

1. **P1：320/375 像素文件夹选项菜单被抽屉覆盖。**菜单层级为 30，侧栏层级为 31；正常点击“搜索”中心被树区域拦截并超时。涉及 [`visual-shell.css`](../../src/web/visual-shell.css) 和 [`prototype.css`](../../src/prototype.css)。待正式 Web 阶段修复并覆盖鼠标、键盘与触屏等交互。
2. **P1：侧栏菜单导航后主区仍不可操作。**在 320/375 像素点击露出的菜单边缘，或在 480 像素正常点击“搜索”后，页面虽切换，抽屉仍显示，主工作区的 `inert` 仍为真；960 像素对照不出现此状态。涉及 [`App.svelte`](../../src/App.svelte) 的文件夹菜单导航及抽屉状态。上述两个问题均未修复，V01 不能整体判为通过。
3. **P1：测试预览没有隔离同源浏览器存储。**在全新隔离 profile 中预置虚构 sentinel 后，打开预览将 `sag.onboarding.seen` 改为 `1`，模拟搜索把 `示例流程` 写入已有 `sag.search.history`。这没有修改真实用户 profile，但证明在同一 origin 使用真实状态时可能覆盖或混入数据；当前应使用独立 profile 和专用回环端口，后续须设计存储隔离并回归。
4. **P1：既有测试覆盖和基线校验不足。**现有脚本没有覆盖上述侧栏菜单路径；且结果中的参考提交号为常量而非运行时核验。须补充自动检查参考 HEAD/文件摘要、隔离测试浏览器存储、逐屏成对截图与差异，并按 Windows 验收基准重新执行。已有测试通过项保留其原范围，不扩大解释。

## Windows 与权限的关键门槛

- [安装器钩子](../../src-tauri/windows/installer-hooks.nsh)依赖产品名、二进制名及安装路径识别旧进程和快捷方式；改名后是否覆盖、定位和恢复必须在隔离 Windows 实测。默认与自定义数据目录均需核查。
- [更新默认配置](../../protocol/src/types.rs)仍指向上游 GitHub，[更新通知](../../src/components/UpdateNotification.svelte)在启动时及运行期间每 8 小时发起检查；下载和安装需要用户操作。升级保留的已有配置及上游签名信任同样必须检查，不能只改默认值。[CLI 安装逻辑](../../cli/src/install.rs)对同版本、不同 build ID 可能保留旧 CLI，因此必须记录实际应用/CLI/服务路径、版本、构建标识及通信。
- 已补充多租户验收：同一用户跨租户不同角色、同租户私有会话、平台管理员未授权拒绝、目录/原件/配置/凭据/索引/任务/事件隔离，以及执行中撤权、重启与恢复。具体隔离单元、授权传播和存储方案仍需在业务对齐后结合真实内核验证。
