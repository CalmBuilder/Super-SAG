# 04 实施顺序与验收矩阵

## 阶段顺序与完整验收条件

各阶段的完整验收条件独立记录；按用户当前指令，macOS 正式分发暂缓，不阻塞 Web 准备。Web 的对应视觉项仍需先有经确认的 Windows 对照，全部视觉和交互对齐后才接通 Web 业务。

| 阶段 | 交付 | 完整验收条件 |
| --- | --- | --- |
| 0 基线 | 固定参考源码、原版 Windows 包、Super-SAG 标识及需求。 | 摘要和引用可复核；明确哪些 Windows 状态仍待实机确认。 |
| 1 Windows / macOS 个人桌面 | 两个平台品牌统一、可打包、安装、运行并保留已有数据，桌面继续本地免登录。macOS 覆盖 Apple 芯片和 Intel。 | 分别在 Windows 和原生 macOS 测试构建、安装、业务、异常及数据保留；记录系统、芯片、构建、包摘要、签名与证据。正常、极值、边界、失败和原功能回归通过后冻结桌面基准；macOS 设备和验证由项目侧负责。 |
| 2 Web 视觉 | 用户同意暂缓 macOS 正式分发并推进 Web；准备并冻结 Windows 基准，优先复用桌面组件，完整还原 Windows 各页面和交互状态。 | 对已确认的 Super-SAG Windows 安装版相应行为，在相同数据、视口、缩放、主题和语言下以真实 Chrome、Edge、Safari 逐屏对照；替身仅用于测试，差异须记录并与用户确认。 |
| 3 Web 业务 | 授权服务器目录、原文件、格式、索引、文件操作、搜索、问答、引用及设置与桌面逐项对齐，完成 Linux 启动。 | 使用真实服务、真实文件和索引，通过正常、极值、边界、失败及真实浏览器验收；对比已验收 Windows 同输入结果。 |
| 4 多租户 | 在等效业务外增加身份、成员、租户、知识库和个人数据隔离。 | 产品入口真实创建 A/B 租户、成员及授权，真实目录索引、检索、问答和跨租户拒绝；浏览器及服务端正常、极值、边界、失败、越权与撤权回归通过。 |
| 5 部署 | 按 `app.sh` 操作，监听 `0.0.0.0:8167`，持久化、升级、备份恢复及部署文档。 | 干净 Linux 环境验证启动、重启、恢复和访问；Web 安全及 Windows、macOS 本地回归闭环。 |

当前按用户指令启动 Web 基准准备和视觉工作。用户反馈 Windows 全部业务及保留数据升级已通过，并提供[验收包摘要与源码提交](验收证据/26-Windows用户验收基准.md)。macOS 正式分发暂缓，macOS 尚未完成的验收独立跟踪。旧 Web 原型仅复用设计与测试经验，不迁入代码和数据库。Web 先完成样式与交互，再逐项接通业务；多租户不抢在业务基线之前。详细切片见[Linux + Web 方案](11-Linux-Web详细实施方案.md)。

## 证据规则

- 每个切片记录 Git 基线、改动范围、真实/模拟环境、测试输入、预期、实际、正常/极值/边界/错误结果、截图、未通过项和风险。
- Web 真实浏览器运行实际页面；视觉测试替身必须单独标明，不能代替真实文件、模型、索引和权限验收。涉及共享代码时须在 Windows 和 macOS 原生桌面回归；未完成的切片标记待验收。平台安装验收必须使用对应平台真实构建的安装包，不能由 Chromium、Vitest 或 Linux 模拟代替。虚拟机测试不能表述为物理设备验收。
- 测试脚本运行前须验证参考提交及逐文件摘要，隔离测试浏览器存储；逐屏保留可比较截图及差异。所选节点的矩形、字体族或前景色检查不是全页面像素一致性证明。
- 隔离演示数据不含个人信息、业务文档或凭据；任何删除/覆盖试验只能操作专为测试准备的数据。正式用户数据不作为测试夹具。
- 每次更新用户文档时同步中文、英文和受影响截图，执行 `npm --prefix docs-site run build`，检查链接和搜索。未经当次指令不发布。
