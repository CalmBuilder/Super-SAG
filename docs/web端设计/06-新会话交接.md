# Super-SAG 新会话交接

进入工作前读取根目录 [AGENTS.md](../../AGENTS.md)，检查 `git status --short --branch` 并保留已有工作。当前版本为 `v0.1.0` 初始化候选版；本机若存在被忽略的 `changelog/`，应先阅读其中维护记录并单独备份，禁止提交该目录。

## 既定顺序

1. 完成 Windows 桌面品牌、构建、真实安装、知识库、文件、索引、检索、问答、设置及 CLI 验收，包含数据保留升级。
2. 以验收通过的 Windows 版为基准，先逐屏还原 Web 样式与交互，再逐项接通同等业务；Web 主要接入 Linux 服务器上经过授权的目录，保留原文件和层级。
3. Web 业务对齐后再增加多用户、多租户及授权隔离；旧 Web 原型只复用设计与测试经验，代码和数据库不迁入。
4. Linux Web 最终使用 `app.sh`，监听 `0.0.0.0:8167`。

## 验收边界

每个小阶段完成正常、极值、边界和失败回归；Web 阶段须通过真实浏览器，涉及桌面共享代码时必须验证 Windows。权限阶段还需覆盖越权、撤权，并从真实产品入口创建第二租户。使用相同测试文件和可比配置核验文件、索引、检索、回答及引用；截图、HTTP 成功、模拟模型或编译成功均不足以证明完整业务通过。

源码保留必要的旧数据兼容，但当前安装包和 Windows 数据迁移不能只凭源码或云测试声称实机通过。构建与用户验收见 [08](08-Windows构建与实机验收.md)，实施顺序见 [04](04-实施与验收.md)。用户文档在 `docs-site/`，按根目录维护规则同步中英文、截图和构建检查。
