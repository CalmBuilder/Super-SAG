## 2. 已由用户确认的目标

1. 产品名称为 **Super-SAG**，桌面与 Web 统一使用用户已确认的标识。素材在 [`assets/branding`](../../assets/branding/)，包括 SVG 和 PNG；仅复制素材不等于应用、安装包或文档完成品牌替换。
2. Windows 桌面保持 SAG-Wiki 原有功能与交互、本地单用户、免登录。新版安装包按**覆盖升级原 SAG-Wiki 并保留原有数据**设计，包括设置、知识库、索引、会话、笔记和原始文件；升级前先用隔离数据演练。
3. 用户会在自己的 Windows 电脑上，按照我们准备的具体步骤执行真实打包/安装或验收并反馈。当前 Linux 环境的模拟、浏览器截图及源码构建不能冒充 Windows 原生安装和覆盖升级验收。
4. 先完成并实机验收 Super-SAG Windows 桌面版，以该安装版作为 Web 正式基准。其后 Web 的第一优先级是**完整还原 Windows 版的样式、布局和交互**，优先复用当前 Svelte 桌面组件和样式；再逐项接通与桌面等效的业务，最后增加多用户和多租户。现有 Web 视觉结果保留为预研，Windows 实机反馈前不能标记正式阶段通过。
5. 知识库数据源、目录组织、文件操作、格式解析、索引、检索、问答、引用和设置都以 SAG-Wiki 为基准。Web 中选择的主要是 **Linux 服务器上经过授权的目录**，保留原文件和目录层级；浏览器上传可以作为补充。
6. 多租户仅增加身份、租户、成员、知识库授权和隔离；参考 WeKnora 的范围限于这些权限机制。一个用户可属于多个租户，角色和资源授权分别生效，租户、库及个人会话不得互相越权。不得用 WeKnora 的知识库业务或界面替换 SAG-Wiki。
7. 用户明确表示**不沿用旧 Web 原型**，并确认已完成的权限与隔离工作只复用设计及测试经验。旧项目 `旧 SAG2/SAG-Wiki 工作区` 的页面、后端、权限代码、数据库结构及数据均不迁入新项目；旧成果和数据保留在原处，不擅自删除。用户允许复用已复制的 Super-SAG 品牌素材，也允许参考旧项目 `app.sh`；旧脚本只是依赖旧后端的包装，因此新项目应按新架构实现启动入口，不能把旧 Web 作为基础搬回。
8. 最终 Linux Web 启动采用 `app.sh`，监听 `0.0.0.0:8167`。开发阶段的仅回环样式预览不等于该服务；实际服务的身份验证、目录和网络安全需随实现验收。
9. 用户指定使用公开仓库 `CalmBuilder/Super-SAG`，通过系统已有 `github-calmbuilder` SSH 别名的推送试运行已通过。代码准备好后可推到该仓库；不得推送至原上游 `origin`，不得把原版安装包、私钥或个人业务数据上传。
