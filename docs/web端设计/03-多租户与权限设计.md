## 权限契约

| 角色 | 租户管理 | 知识库操作 |
| --- | --- | --- |
| Owner | 管理租户、成员和授权；所有权转移/删除等高风险操作遵循明确确认和审计。 | 在所属租户内按明确的库管理权限操作；不能访问其他租户。 |
| Admin | 管理被授予范围的成员和租户配置，不得单方面夺取 Owner 或使租户失去有效 Owner。 | 依据租户策略管理授权及已授权库，不自动跨租户。 |
| Contributor | 在授权范围内创建或编辑知识库与文档。 | 只读取和编辑本人被授予的库及资料。 |
| Viewer | 不管理租户或成员。 | 只读取被授予的库和资料，搜索/问答不得引用无权内容。 |

平台权限不自动赋予租户成员身份、知识库访问或个人会话读取。一个用户可加入多个租户；当前租户切换不得混入上一租户的数据、文件、任务或事件。会话、草稿、历史和凭据按实际归属隔离；文件、目录授权、索引和后台服务存在实质边界，不能只靠前端隐藏或不同目录名称。

目录访问、检索、引用、原文、编辑和事件/取消都必须在服务端授权，并在撤权后拒绝新的请求及旧事件。需要涵盖路径穿越、软链接、硬链接、竞态、跨租户猜 ID、空授权、共享会话及停用用户；涉及独立文件系统/容器隔离的实现方案须在业务对齐阶段完成后结合真实内核与部署环境设计并验证。

## 隔离单元与运行时边界

当前 SAG 核心存在单一数据目录、Store 及按数据目录保存的配置和凭据，不能仅在请求或界面附加租户 ID 就宣称隔离。正式多租户实施前，须选择并验证租户/知识库的数据、目录、索引和存储隔离单元；明确个人会话和草稿、配置与密钥的归属；确定缓存、后台索引、检索、流式事件、工具/MCP、CLI/Agent 的身份与授权传播。对任务进行中撤权，须在输出或写入前重新校验或中断，并验证重启、备份及恢复后的隔离。技术选型及迁移策略需在真实内核和部署环境中证明，当前尚未选定或实现。

## 最终多租户验收

通过产品入口真实创建两个租户与成员，并分别在各自授权服务器目录中建立真实索引、检索和问答；同租户再设置授权库与私有库，核验四角色及撤权。对照结果来源、文件摘要、会话归属、持久化、审计和实际拒绝；SQL 直接插入测试租户只能测试隔离，不能证明租户开通完成。每一步通过真实浏览器以及正常、极值、边界、失败和并发测试。

至少覆盖同一用户在两个租户担任不同角色、同租户不同用户的私有会话与草稿、无成员或资源授权的平台管理员被拒绝，以及跨租户目录、原文件、配置、密钥、索引、任务和事件的读取/写入拒绝；对运行中撤权、旧事件及备份恢复后的访问分别留存真实结果。
