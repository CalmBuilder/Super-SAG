## 已决定事项

1. 正式名称为 **Super-SAG**。已选定的 SVG 和 PNG 放在 [`assets/branding`](../../assets/branding/)；该目录只是素材，尚未说明桌面应用完成了品牌替换或商标注册。
2. 新 Windows 安装版覆盖原 SAG-Wiki 并保留数据，桌面继续本地、单用户、无需登录；必须先在隔离测试环境演练，再提供用户可审查的实际验收步骤。不能以改名后首次全新安装成功代替升级验收。
3. Windows 实机的打包/安装验证由用户在自己的 Windows 电脑按步骤执行并反馈。需要的具体工具、版本、安装包和脱敏验收记录将在可执行阶段给出；Linux 编译和模拟截图不能冒充 Windows 验收。
4. 先完成并实机验收 Super-SAG Windows 桌面版，再以验收通过的该安装版为正式 Web 基准；Web 在 Linux 上运行，先完整对齐界面与交互，再逐项对齐业务、索引、原文件和问答，视觉样例不能冒充真实功能。已有基于原版源码的 Web 视觉切片只是预研，待新 Windows 基准冻结后逐项复核。
5. Web 增加多用户、多租户和按知识库授权，参考 WeKnora 仅限身份与权限；Windows 桌面不接入多租户。
6. 新 Web 从空白环境开始；旧 Web 的代码（包括权限代码）、页面、后端、数据库结构和数据均不迁移。旧原型和原数据留在原处，不能因废弃旧项目而自行删除；已完成的权限与隔离工作仅可复用设计及测试经验，不作为本项目已实现功能。
7. Web 按新架构实现 `app.sh`，需提供启动、停止、状态、日志等操作并监听 `0.0.0.0:8167`；不复制依赖旧 Web 实现的包装脚本来冒充可启动程序。

用户提供的 Windows 截图包含实际资料名称和会话，未经脱敏不得写入仓库；用于可复现验收的演示资料应为虚构数据。

## 工程原则

- 正常、空值、极值/边界、失败和权限检查均要对应实际结果；每个 Web 小阶段使用真实浏览器，截图必须标明真实或测试替身。
- 涉及桌面共享代码的小阶段还须在真实 Windows 桌面回归相关行为；反馈前只能标记待 Windows 验收，Vitest、Linux 或浏览器替身不能代替。
- 界面差异逐项记录；Web 无法使用的原生系统能力，要给出功能等效方案并与用户确认差异，不能静默删减。
- 修改功能、操作、安装方式或支持范围时，同任务更新 `docs-site/content/docs/` 中英文文档及受影响的脱敏截图；文档构建和链接/搜索检查以仓库 `AGENTS.md` 为准。
- 当前任务不授权发布或推送。任何安装包、更新源和下载链接必须准确标记其来源及发布状态。
